# 数据、安全与身份归并

在连接文件、API、数据库、聊天记录或写回动作前读取本文件。

## 数据角色

每个数据源必须标记一种权威角色：

- `source-of-truth`：业务事实的维护位置。
- `snapshot`：为展示或性能生成的只读快照，可以重建。
- `derived`：按透明规则计算的指标或判断，必须能追溯输入。

工作台默认读取真源或快照，不因用户在页面看到某个值就让该页面成为新的真源。

## 字段与来源

每个重要字段记录：

- 字段含义和类型；
- 来源 ID；
- 更新方式和更新时间；
- 缺失、冲突、过期时的显示规则；
- 敏感等级：`public`、`internal`、`personal`、`sensitive`。

不得把不同来源中同名但含义不同的字段直接合并。派生指标应显示计算口径或证据入口。

## 身份归并

把多次通话、会话、邮件和笔记串到同一对象时，按以下优先级匹配：

1. 已有稳定 ID；
2. 用户明确确认的映射；
3. 多字段组合且冲突可审计；
4. 名称近似只能作为候选，不能自动合并。

保留来源记录 ID 和原始链接。出现冲突时显示「待确认」，不要静默覆盖。

## 动作权限

| 动作 | 默认边界 |
| --- | --- |
| 打开已知文件/页面 | 可在规格确认后执行 |
| 以关键词打开搜索 | 显示查询词和目标站点 |
| 修改真源 | 操作前确认；记录改动对象和结果 |
| 运行命令 | 区分只读与有副作用；后者操作前确认 |
| 发送消息/通知 | 对象、内容、渠道、时机均需确认 |
| 自动执行 | 仅在触发条件、失败处理和撤销边界明确后启用 |

任何 `update-source` 或 `run-command` 动作都不能把 `confirmation` 设为 `never`。涉及敏感数据的自动写回还需要明确 `privacy.writeAuthorization`。

## 敏感信息

客户身份、联系方式、健康、保险、财务和家庭信息默认按 `sensitive` 处理：

- 优先保留在本地或用户指定的受控系统；
- 工作台只显示当前决定所需的最少字段；
- 日志、截图、测试和公开示例使用脱敏数据；
- 凭证不写进 Skill、规格、源代码或示例；
- 外部链接和搜索不得把敏感字段拼进公开 URL，除非用户清楚授权并理解风险。

## 失败态

至少设计：来源不可访问、数据为空、数据过期、身份冲突、字段格式错误、无写权限、动作执行失败。失败态应说明事实、影响和可执行下一步，不得以旧值伪装成功。
