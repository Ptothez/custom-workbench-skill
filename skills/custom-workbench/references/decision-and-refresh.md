# 判断与持续更新

仅在工作台需要确定重点、自动整理行动或持续归拢记录时使用。项目名称、金额、数量、期限和当前重点留在项目真源，不写成通用技能常量。

## 判断口径

从当前要求、明确决策、项目真源及近期记录提取：方向／使命（如适用）→阶段目标→当前瓶颈→周期承诺→今日动作。周承诺和今日提案分开；未确认的目标数字、承诺和期限不得写成已批准。

记录有顺序的优先依据、适用时间和出处。用户确认目标贡献高于期限时，期限只是次要条件；风险等是否可越过该口径，须有明确条件和依据。不能把 Agent 最近的运维工作当作业务重点。

候选来自登记行动、有出处的目标断点和明确承诺，不只从旧数组截前三。等待、已完成、取消及被替代事项单列或退出，状态不明先核查。候选不足时显示少于焦点上限，不凑数。

规则负责明确约束，开放判断可用模型或人工审阅。分别标识规则生成、模型判断、本人确认；人为权重不是客观最优解。每条选择关联真实候选、出处和为什么现在做，不虚构池外任务。

## 低阻力确认

已有记录能够取得的信息预填。用户要求自动整理时，不以每日手填作为启动前置。首屏少量行动及一句依据，原因、步骤、历史按需展开；后台运维、制度和完整队列归分区。

需要本人决策时：提案→确认／改标题／删换→保存计划→执行与反馈。支持取消、重试、双窗口冲突、重开保留及确认后调整；新来源提出调整建议，不静默替换确认计划。

提案 ID、源动作 ID、确认计划 ID 关联但不混同；确认后保留依据、出处与验收口径。确认安排不是已执行，也不等于授权发消息、付款、部署或新增权限。

## 更新链路

为来源记录权威位置、覆盖范围、业务日期／采集时间、处理水位、失败和去重键。读取聊天不等于事件已进入快照；不能访问全部聊天时说明实际覆盖范围，不把文件同步时间当事件发生时间。

逐段验原始记录→提取／封存→快照→候选→判断→提案→确认计划→页面→执行入口→反馈真源。管道坏了先定位，不在坏快照上换排序器。积压重放防重复、保原件，核对每条是否生效或被后续决策替代。

焦点上限与完整任务池分开。超限保留完整池、出处及告警／继续位置，不整批丢证据，也不把无判断截断叫高优。

分别定义来源采集、语义归并、重新判断和页面刷新。刷新页面不等于重新采集，读取新文件不等于模型重算。触发可为打开、跨日、事件或手动，频率及成本按场景决定。

缓存考虑日期、目标／排序版本、处理过的来源版本及确认／反馈版本。确认计划冻结，输入变化提示重审。模型只接所需摘要，标明摘录和遗漏边界，不装入全部私人资料。

## 失败与反馈

模型调用有互斥、超时、有限重试／冷却、诊断和恢复路径，不后台无限扣费。不可用时用批准规则并明确标识，或保留确认计划提示暂不可重算；不得把旧模型结果换上新日期。

断点依据真实期限、最后有证据的进展及出处，不将首次采集当最近进展。超期提示核查，不自动证明失败或挤掉全部主线。完成、取消、延期、等待和新信息写回各自真源，不能只改页面导致下次又复活。

## 业务验收

- 无需先录入就可看行动与出处；用更早到期但贡献较低的反例验证约定口径。
- 完成、等待或替代一条任务后，候选与参考队列更新；未确认提案重算，确认计划不被覆盖。
- 确认、修改、取消、跨日、重开、双窗口、来源变化后，计划与依据仍正确。
- 来源不可读、积压未处理、模型超时、焦点超限都有解释，恢复不重复落库。
- 点行动到正确聊天、文件、对象或执行位置，不只到泛项目首页；内页、外页与后退可返回。
- 选择不合适时可追溯来源遗漏、目标口径、状态或选择错误，修正后重验。标题／格式／点击正常不证明业务选择合格。
