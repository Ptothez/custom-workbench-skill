# 反馈与经验闭环

适用于用户希望工作台意见在后续执行中真正被采纳的情况。只收集一次性表单而无复用需求时，不强加经验库。

1. 原话完整保存，保留对象、时间、版本和来源；后续解释与抽象另存，不覆盖原意见。
2. 明确哪些由用户决定，哪些由 Agent 继续核查。用户保存后退出待判断，待执行与已落实分开。
3. 具体落实留来源反馈 ID、结果和实际证据；未执行或阻塞不能报已落实。后续执行先读取这些记录。
4. 相同意见合并跟进但保留每条原文。适合跨对象／场景复用的经验才提出候选，写适用范围、边界、反例及冲突。
5. 用户采用不等于验证完成；经独立场景验证再生效，失效可停用，历史来源保留。不要把一次失败写成超细且永久叠加的禁令。
6. 验收完整链：写入意见 → 重开仍在 → 具体执行有回执 → 候选未批准不生效 → 验证与采用满足后 → 下一次执行上下文实际读入。

首屏只说用户要判断什么、Agent 建议什么、可选决定是什么。完整路径、内部编号、哈希和日志按需展开。多个旧入口归并时对照所有旧事项与意见，不用「数据还在另一个页面」冒充统一。
