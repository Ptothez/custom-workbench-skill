# 信息架构与视图选择

在问题契约确认后、创建 `workbench-spec.json` 时读取本文件。

## 先选择首要组织单元

| 组织单元 | 适合的任务 | 常见导航结构 |
| --- | --- | --- |
| 人物 | 客户、成员、患者、学员关系维护 | 人物列表 → 人物详情 → 互动/事项 |
| 项目 | 目标、交付物、跨团队推进 | 项目列表 → 阶段/里程碑 → 任务/证据 |
| 案件 | 工单、理赔、售后、咨询个案 | 待处理队列 → 案件详情 → 时间线 |
| 资产 | 设备、投资、房产、内容资产 | 资产组合 → 单项详情 → 状态/事件 |
| 时间周期 | 日复盘、周计划、月报、盘前盘后 | 当前周期 → 分段视图 → 历史周期 |
| 混合 | 同时存在稳定对象和周期工作 | 选一个主导航，其他维度作为筛选或二级入口 |

混合不等于把所有维度都放进一级侧栏。判断标准是：用户最常从哪个对象进入工作，以及哪个对象在一段时间内保持稳定。

## 用问题选择视图

| 用户要回答的问题 | 首选视图 | 不适合的替代 |
| --- | --- | --- |
| 现在最该处理什么？ | 队列/优先列表 | 只有总指标 |
| 每个对象处在哪个阶段？ | 看板/阶段列表 | 无状态含义的卡片墙 |
| 多个对象如何横向比较？ | 表格 | 每个对象一张孤立卡片 |
| 一个人/案件发生过什么？ | 时间线 | 按文件名散列的附件区 |
| 一个对象的完整上下文是什么？ | 实体详情页 | 把所有字段塞进总览 |
| 总体趋势或风险如何？ | 指标与趋势 | 只显示当前数字 |
| 何时要做什么？ | 日历/时间轴 | 只有静态截止日期文本 |
| 一个周期前后发生了什么？ | 周期复盘/对照页 | 混成一张长期总表 |

每个视图都要在规格中写 `questionAnswered`。回答不了明确问题的模块应删除或降级。

## 导航与层级

1. 一级导航表达稳定的工作区域或首要对象集合。
2. 二级导航表达对象、保存视图或子流程。
3. 事件型子项只有在经常被单独进入时才放入导航；否则留在详情页时间线。
4. 同一对象的多次会话通过稳定身份键串联，并保留原始来源链接。
5. 列表项至少支持名称、状态、风险/优先级和下一行动中的必要组合。

示例：保险顾问可能使用「客户 → 沟通记录」；量化复盘可能使用「盘前/盘后 → 当前周期」；内容团队可能使用「栏目 → 选题 → 稿件阶段」。它们不是同一种页面换标题。

## 模块优先级

用以下顺序删减：

1. 支持当天决定和行动的模块；
2. 解释当前状态与证据的模块；
3. 提供历史脉络和趋势的模块；
4. 低频背景资料；
5. 只为视觉丰满、没有行动价值的内容。

首屏优先显示第 1、2 类。详情页承载第 3、4 类。第 5 类不进入成品。

## 状态定义

状态必须有可验证含义。例如「已完成」应绑定成果或真源记录，「高风险」应绑定阈值或明确人工判断。不要使用无法解释的进度百分比；没有真实计划基线时，显示阶段、证据与下一步更可靠。
