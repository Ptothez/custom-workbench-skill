# 保险顾问工作台示例

本文件只用于展示如何从职业任务推导结构。不得把字段照搬到其他行业，也不得在示例中放入真实客户资料。

## 问题契约示例

```text
使用者：独立保险顾问
核心决定：今天优先跟进谁；每位客户目前缺什么信息；下一次沟通要解决什么
首要组织单元：客户
层级：客户 → 沟通/会议/材料事件
当前摩擦：多次沟通散落在不同文件，容易忘记承诺和下一行动
成功证据：1 分钟内找到高优先级客户，并打开最近沟通依据和下一行动
```

## 推导出的结构

### 左侧导航

- 「待处理」：按下一行动、资料缺口或到期风险排序的队列。
- 「客户」：客户列表，可按阶段、风险、家庭或负责人筛选。
- 「资料」：产品细则和通用材料，不与客户档案混成一个真源。

客户可展开最近沟通，但全部通话不必都塞进侧栏。高频单独进入的第 1/2/3 次沟通可以成为二级项，其余放在详情页时间线。

### 客户详情

按实际业务和授权选择字段：

- 当前目标与顾虑；
- 家庭与责任概况；
- 已有保障和明确缺口；
- 健康/核保相关信息；
- 当前阶段和下一行动；
- 第 1/2/3 次沟通的时间线、原始记录和承诺；
- 推荐方案及其依据；
- 已确认的产品细则、文件和内部链接。

健康、家庭、保单和联系方式均为敏感信息。列表页不应暴露不影响当前决定的详细字段。

### 视图组合

| 视图 | 回答的问题 |
| --- | --- |
| 待处理队列 | 今天最该联系谁，原因是什么？ |
| 客户详情 | 这个客户的完整上下文和下一行动是什么？ |
| 沟通时间线 | 前几次谈了什么，承诺和变化在哪里？ |
| 阶段看板 | 客户整体分布在哪些阶段？ |
| 保单/方案表格 | 同一客户的已有保障和候选方案如何比较？ |

只有当总体指标会改变顾问的实际决定时，才增加指标页；不要用「客户总数」等数字装饰首页。

## 动作边界示例

- 打开经确认的沟通原文或产品文件：只读动作。
- 打开浏览器检索公开产品信息：不得把客户健康信息拼入搜索词。
- 更新下一行动或客户阶段：写回客户真源前确认，并保留修改记录。
- 发送提醒或客户消息：必须确认接收人、内容、渠道和时间。

## 验收场景示例

1. 进入匿名客户「客户 A」，看到三次沟通按时间排序，并能打开每次沟通的原始记录。
2. 最近沟通没有下一行动时，页面显示「待补充」，而不是自动生成一个事实状态。
3. 健康字段只在获授权的详情视图出现，不进入总览、截图或测试数据。
4. 产品链接失效时显示来源不可用及替代搜索动作，不继续展示为已验证资料。
