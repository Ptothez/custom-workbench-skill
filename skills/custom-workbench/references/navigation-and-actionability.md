# 导航与行动可用性

仅在有多层页面、内嵌视图、跨模块管理，或需要降低今日行动理解门槛时读取。单个名称或颜色修改不要求重建整套架构。

## 一、盘点实际页面，再确定层级

从代码和浏览器取出页面、标签、弹窗、文件入口及外部后台。逐项记录：稳定 ID、所属父项、名称、回答的问题、进入路径、退出方式、来源和副作用。概览与完整明细可以并存，但要区分角色，不能重复造账。

- 一级是稳定工作区域，二级按使用目的分组，三级是对象或视图。层数不是固定上限，增加层级须能减少查找或操作负担。
- 一个页面有明确的常用归属。跨区捷径可多，但不能改变上一级的含义。
- 先区分决策、经营、服务维护、故障与资料等工作性质，再组织入口；名称来自使用场景，不强制套用这组分类。
- 用 `interactionMap.nodes` 记录 id、parentId、route、label、kind；外部入口记 openMode。运行 `node scripts/validate-navigation-contract.mjs <spec.json>` 检查重复、孤儿、循环。结构通过不代表实际好用。

依据：稳定分组和明确映射；用实际查找任务检验分类。

## 二、统一当前位置与导航责任

1. 明确外层或内层谁拥有路由与历史。共同外框下，内部切换同步外层地址、选中项和当前位置，不让两套路由互相覆盖。
2. 「返回上一级」是父项；浏览器后退是访问历史。标签与行为分开；直达书签也有确定父项。
3. 刷新、重开、深链接及前进／后退还原同一页面；无效路径降级到可辨识的有效入口。
4. 内页保留共同项目导航与当前位置，去除重复站名、侧栏和冲突返回按钮。外部控制台或文件另开受控上下文，保留工作台。
5. 返回列表时保留合理筛选、分页、展开或滚动。密码、开通码、人工确认和有副作用状态不因缓存自动恢复执行。
6. 旧独立页书签回到同一受控入口，不形成第二套后台。下载、外部链接、同页锚点与跨区捷径分别处理，不能一律重定向。

依据：系统状态可见、识别优于回忆；单一路由是实现选择，不限定技术框架。

## 三、今日首屏从理解走向动作

以不熟悉内部术语的用户阅读实际任务，而非仅检查字段是否齐全。

| 层次 | 应呈现 | 失败信号 |
| --- | --- | --- |
| 未展开 | 动词＋具体对象、必要状态、可立即做的第一步 | 抽象名词或内部缩写，先读长文才知道干什么 |
| 展开 | 有序做法、可观察完成标准、准确入口 | 重复宏观使命、做法和完成标准完全相同、只到泛项目首页 |
| 按需核对 | 为什么现在做、出处、原任务与生成时间 | 隐藏来源，或把全部证据塞进首屏 |

- 已知明确入口就直达页面、文件或对象；现实沟通任务可只给第一步，不伪造自动执行按钮。
- 展示改写不改变任务身份、来源、排序、确认状态和权限；不能借此改价格、承诺、范围或完成事实。
- 项目专属指引绑定来源；原任务实质改变时失效或重新核对，不能长期覆盖新任务。
- 不发明步骤填空。缺少对象、权限或输入时，显示具体待取得条件，不用「继续推进」冒充行动。
- 不把字数、点击次数或每日三件当作通用标准；核对用户能否说明任务、第一步、入口与完成证据。

依据：缩小理解到执行的距离、渐进呈现；真实可执行性优先于文字更短。

## 四、视觉与业务边界回归

先定义共享字号、标题层次、底色、边框、语义颜色、按钮和表格，再对比实际页面。收敛重复标题、装饰口号、子系统默认样式和嵌套滚动；原来清楚的模块只修发现的问题，不改其业务规则。

验收矩阵：

1. 常用入口到叶页、叶页回父页，跨区后当前位置正确。
2. 刷新、深链接、前进／后退、旧书签、异常与空数据。
3. 长列表筛选后进入详情再返回，筛选与结果一致，不是只恢复表单文字。
4. 今日主项的原名称、展示名、第一步、完成标准和入口逐项核对，实际点击内部入口。
5. 已有清楚的模块、只读权限和写入确认无回归；不拿真实客户做封禁、结案或退款测试。
6. 桌面和窄屏真实截图；主列表、展开、内页、弹窗属于同一视觉系统。私密样本留在受控位置。

分别记录导航、行动理解、视觉和业务选择证据。修改者自评须注明，不把脚本通过当作用户满意，也不把产品回归等同于技能盲测。
